# 方法与解释边界

## 从谱到 Skill

1. 固定上游提交并审计 71 首整曲与 408 份分段谱。
2. 逐事件解析音高、时值、休止、和声音符与 staccato 泛音代理。
3. 计算局部音程/节奏母题、段落密度/音区/留白/跳进、全曲弧线与高潮位置。
4. 将每曲的文化背景、意象空间、运动方式与情感转变和音乐观察并置。
5. 输出 71 条组合式 Skill；运行时只把它们当作先验和参照，不复刻原曲。

## 已知限制

- MusicXML 忽略了减字谱中的大量演奏法，不能据此学习完整的吟猱绰注语法。
- staccato 是数据集作者用来转写泛音的代理，只在本语料内按此解释。
- 拍号由上游程序自动生成，不作为古琴节拍美学的直接证据。
- `title_inference` 表示产品意象解释，不是历史曲解；运行时权重低于正式题解或文学原典。
- 五音框架保留为传统文化映射。调心是 wellbeing 场景设计，不宣称医疗疗效。
- 《内经》明确配属、传统理论推演、现代产品策略分层保存；“先承接再转化”归入产品策略。
- 调心先判断和、泄、制、养，再选择音乐方向，不把情绪映射成固定音或固定转音序列。

## 质量门槛

- 所有曲目、分段和文化记录必须可一一关联。
- 数值特征不得出现解析失败或非有限值。
- 原始整曲谱与分段谱不一致时记录差异，不私自修补。
- 母题只保留短片段，用于轮廓与节奏变换；禁止长段复制。
- 每次构建执行 `npm run validate`。
