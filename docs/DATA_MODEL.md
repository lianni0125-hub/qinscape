# 分层 Skill 数据模型

Skill 不是一段长提示词，而是一组可查询、可组合、可审计的知识对象。

## 三个音乐尺度

1. **局部（micro）**：2–8 音动机、音程轮廓、节奏型、装饰密度、泛音代理、起止音与停顿。
2. **段落（meso）**：每个原谱分段的长度、音区、密度、调式音级重心、张力与疏密变化、段落功能候选。
3. **全曲（macro）**：段落序列、密度/音区/活动度弧线、材料复现、高潮位置、收束方式及不同曲目的结构家族。

## 四组实体

- `works`：曲目身份、谱源、定弦、传谱与记谱信息。
- `sections` / `notes` / `motifs`：从 MusicXML 计算的观察事实。
- `work_culture` / `cultural_evidence`：背景、母题、空间、时令、人格理想、叙事阶段及来源。
- `composition_skills`：把观察与文化解释压缩成生成约束；必须注明证据强度和适用范围。

## 两条产品路径

- **写意**：用户意象 → 意象场景图 → 结构弧线 → 共享作曲 Skill。
- **调心**：用户状态 → 目标状态 → 五音/气机的产品规则 → 意象场景图 → 共享作曲 Skill。

二者共享古曲结构语法。调心在共享核心前增加状态推理、五音路径、禁忌与渐变策略，并在选材和配器时提高稳定、呼吸感、可预测性等约束的优先级。

调心知识必须标明三层来源：

1. 《黄帝内经》原文明确给出的传统配属；
2. 基于五行生克及后世理论所作的传统推演；
3. 琴境为可用性和体验安全所设计的现代策略。

“先同频承接、再渐进转化”属于第三层，不表述为《黄帝内经》的原始处方。运行时先判断“和、泄、制、养”，再决定五音主次，不使用固定的商→宫→角之类模板。

## 生成端中立接口

当前阶段不绑定任何 MIDI 模型，但每条作曲 Skill 应能落到这些中间变量：

- `form_plan`：段落数、段落功能和时长比例
- `pitch_plan`：中心音、音域、级进/跳进比例、终止音
- `rhythm_plan`：速度区间、事件密度、长短时值比例、留白
- `texture_plan`：单线、持续音、呼应、伴奏占位
- `gesture_plan`：泛音代理、重复、上行/下行、波浪/回环轮廓
- `imagery_arc`：各段的景、情、势与转折
